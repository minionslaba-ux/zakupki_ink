# Shtark Flow — пакет для GitHub Pages

Самодостаточная сборка портала **Shtark Flow** (мультикомпанийный финансовый аналитик). Сборка: **2026-07-02 · r22** (метка видна в шапке портала).
Включены последние изменения:
- **Казначейство / заявки на оплату:** статус согласующего выбирается из выпадающего списка — **«На согласовании» → «К оплате» → «Оплачено»**. Исправлен баг, когда выбор «Согласован» сразу переводил заявку в «Оплачено».
- **Оплата полностью или частями:** в карточке заявки можно внести фактическую оплату; остаток к оплате и статус («К оплате» → «Частично оплачено» → «Оплачено») пересчитываются автоматически.
- **Контрольный срок оплаты** рассчитывается автоматически из условий оплаты (договор → карточка контрагента) с возможностью ручного ввода.
- **Прайс контрагента:** позиции подбираются из справочника номенклатуры по **артикулу / наименованию / выбором** или вводится новая; цена — **с НДС**, фиксируются дата ввода и история изменений.
- **Динамика цен на сырьё:** график роста/снижения цен во времени по всем поставщикам.
- **Импорт справочника контрагентов из Excel** (Закупки → Поставщики/Контрагенты): система сама распознаёт колонки выгрузки 1С (Контрагент, ИНН, КПП, Юр/Физ, Страна, ОКПО и др.) и заполняет карточки.

## ⚠ Доступ: шлюз-404 ОТКЛЮЧЁН
В этой сборке жёсткий шлюз убран — портал открывается напрямую по адресу Pages, **ключ в адресе больше не нужен**.
Если раньше видели «404 Not Found» — это была защитная заглушка, теперь её нет.
Вернуть защиту: в исходнике `Калькулятор NEV.dc.html` вверху поставьте `var GATE_ON = true;` и пересоберите — тогда доступ снова только с `?k=shtark-erp-2026`.

## Что внутри
- `index.html` — весь портал (HTML+CSS+JS инлайн).
- `catalog.json`, `catalog-chem.json`, `nev_data.json`, `nev-chem.json`, `tcalc-chem.json`, `sebest-chem.json` — стартовые справочники-фолбэки первого запуска (боевые данные приходят из облака).
- `.gitignore` — защита ключей и боевых данных от попадания в репозиторий.
- `.nojekyll` — отключает обработку Jekyll на GitHub Pages (отдаёт файлы как есть).

## Деплой на GitHub Pages
1. Создайте репозиторий и положите туда содержимое этой папки (`index.html`, JSON-справочники, `.gitignore`, `.nojekyll`).
2. Settings → Pages → Source: `Deploy from a branch` → ветка `main`, папка `/ (root)`.
3. Через 1–2 минуты портал доступен по адресу `https://<логин>.github.io/<репозиторий>/`.
4. Если после обновления видите старую версию — жёсткий перезагруз: **Ctrl+Shift+R** (Cmd+Shift+R на Mac). Проверьте метку «сборка 2026-07-02 · r22» в шапке.

## Почему система не сломается
- **Данные отделены от кода.** Архив файлов, логи безопасности, задачи, маппинг, KPI, ключи AI хранятся в `localStorage` / `IndexedDB` / облаке (Firebase/Supabase) — НЕ в файлах репозитория. `git push` нового `index.html` их не затирает.
- **Ключи не в репозитории.** Серверные ключи (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `DEEPSEEK_API_KEY`, `OCR_API_KEY`, service-account Firebase) — только в Environment Variables серверless-прокси (Cloudflare/Vercel/Netlify) или в защищённой админ-панели. Firebase web-config (клиентский apiKey) — не секрет, доступ ограничивают Security Rules.
- **`.gitignore`** не даёт случайно закоммитить `.env` и `serviceAccount*.json`.

## Обновление версии
Не редактируйте `index.html` вручную — это скомпилированный файл. Меняйте исходник `Калькулятор NEV.dc.html`, пересоберите автономную версию и замените `index.html`.

Полное руководство по деплою и архитектуре — в `DEPLOY.md` корня проекта.
