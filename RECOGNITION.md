# Ядро распознавания документов Shtark Flow

Модуль обучаемого распознавания первичных документов, загружаемых в систему (счета на оплату, счета-фактуры, УПД, товарные накладные, коммерческие инвойсы ВЭД). Цель — автоматически определять **все значимые для учёта параметры** (номер, дата, поставщик, ИНН, валюта, НДС, итог, построчная номенклатура и суммы), правильно определять **раздел размещения** документа и запускать **сквозной пересчёт** данных системы.

## Где в коде (единая точка истины)
Класс `Component` в `Калькулятор NEV.dc.html`:

- **Чтение файла** — `dlReadFile(file)` → диспетчер по расширению: `dlReadPdf` (PDF, текстовый слой через PDF.js, группировка в строки/колонки по координатам + поиск строки-шапки товарной таблицы), CSV/TXT, XLSX (`XLSX.read`). Строка-шапка товарной таблицы во всех форматах ищется единым методом `dlFindHeaderRow(aoa)` (по ключевым словам, а не «первая непустая»), поэтому преамбула счёта («Счёт № … от …», «Поставщик: …») не ломает разбор номенклатуры. Для CSV/TXT также запускается `dlExtractMeta` + `dlAugmentPdfMeta` (шапка: поставщик/№/дата/НДС/итог), как для PDF.
- **Извлечение шапки/подвала** — `dlExtractMeta(aoa, hr, fname)` (поставщик, покупатель, ИНН, №, дата, НДС, итог, валюта) + `dlAugmentPdfMeta(meta, clean, fname)` (доп. сканирование плоского текста PDF: «Счёт на оплату № … от …», «Всего к оплате», «в том числе НДС», ООО/АО/ИП + ИНН). Русские даты («1 июля 2026 г.») — `impDateAny` / `ruMonth`.
- **Семантическое ядро (самообучение)** — `aiMatrix` (матрица синонимов в `ai_semantic_weights`, глобальные + по компаниям), `aiClassify(word)`, `trainSemanticCore(word, field, opts)`. Каждое ручное сопоставление колонок аналитиком обучает ядро; правило с 3+ подтверждениями поднимается в глобальную базу.
- **Уверенность распознавания** — `dlMapIsConfident(map)` (есть номенклатура + метрика), `dlSemanticConfident(headers, rows)` (поля распознаны ПО СМЫСЛУ, а не угаданы по типу).
- **Определение раздела** — `dlDetectCategory(headers, rows)` → раздел/отчёт для размещения; диалог «куда поместить» с режимом «по алгоритму системы».
- **Fallback к внешнему ИИ** — `executeExternalAiFallback(fileData, companyId)` при неуверенности: внешний ИИ возвращает `{identified_category, mapping_schema}`, данные вносятся автономно, карта маппинга сохраняется в матрицу с максимальным весом (следующий такой файл распознаётся локально, без платного API).
- **Извлечение инвойса ИИ** — `impAiInvoice(d)` + встроенный промт `docRecogPrompt()` + слияние `mergeInvoiceAi(doc, ai)` (для окна «Загрузить счета (ИИ)» в казначействе).
- **Импорт-конвейер** — `impAddFiles` → `impConvert(target, d, map, file)` → редактируемый документ целевого модуля → `impCommit()`.

## Встроенный промт (docRecogPrompt)
Роль: ядро распознавания первичных документов. Возвращает СТРОГО JSON:

```json
{
  "doc_kind": "invoice|upd|waybill|proforma|other",
  "doc_no": "<номер>",
  "doc_date": "YYYY-MM-DD",
  "supplier": "<продавец/поставщик>",
  "supplier_inn": "<ИНН продавца>",
  "buyer": "<покупатель>",
  "currency": "RUB|EUR|USD|CNY",
  "vat_rate": 0,
  "vat_amount": 0,
  "total": 0,
  "lines": [{ "name": "", "qty": 0, "unit": "", "price": 0, "sum": 0 }]
}
```

Правила: числа с точкой-разделителем без пробелов; поставщик = кто выставил счёт (не покупатель); `total` = «Всего к оплате»/«Итого»; `vat_amount` = «в том числе НДС»; каждая товарная позиция — отдельный `lines[]`; отсутствующие поля = "" или 0; раздел размещения таких документов — «Заявки на оплату (казначейство)».

## Поток «Счёт → Заявка на оплату» (казначейство)
1. Казначейство → «📎 Загрузить счета (ИИ)» → перетащить PDF/Excel счёта.
2. Ядро распознаёт поставщика, №/дату счёта, НДС и построчную номенклатуру (при подключённом внешнем ИИ — дополнительное извлечение по `docRecogPrompt`).
3. Пользователь отмечает галочками позиции к оплате, при необходимости задаёт **частичную сумму** по позиции (колонка «К оплате ₽»).
4. «Внести» → создаётся заявка: сумма = Σ отмеченного, **оригинал счёта вкладывается** (IndexedDB `shtarkflow_files`) и открывается из реестра/карточки.
5. Реестр заявок: фильтры по датам/поставщику/статусу, колонки «% оплаты» и «плановая дата», проваливание в карточку, отметка фактических платежей (частичная/полная), пометка «на удаление», корректировка.
6. Отчёт задолженности поставщика показывается прямо в форме создания заявки: текущая задолженность, просроченная часть, перечень непогашенных заявок с проваливанием.

## Сквозной пересчёт
После внесения — `scheduleAutoRecalc` / БДДС (`buildTreasury30`) учитывает непогашенный остаток заявок (без оплаченных частей и без помеченных «на удаление») в казначейском календаре на 30 дней и сигнализирует о кассовых разрывах.
